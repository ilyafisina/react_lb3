### Предварительная подготовка: Авторизация в БКС Онлайн

**Метод:** `POST {{Server}}/login`

**Тело запроса:**

**Ожидаемый результат:** В разделе Cookies ответа появятся объекты `JSESSIONID` и `_bcspks`, которые будут использоваться для аутентификации во всех последующих запросах.

**Логи:** После авторизации определяем ноду (ara или wasrv), к которой подключен пользователь, и смотрим логи по пути `{{Нода}}/api/bcs-api.log`.

### Шаг 1. Получить список имеющихся персональных документов пользователя

**Метод:** `POST {{Server}}/document/getPersonalDocument`

**Тело запроса:**
```json
{}
```

**Описание:**
Метод MO002 — предназначен для получения списка активных ранее добавленных в БД портала документов пользователя. Документы группируются по категориям (GFO_PERSONAL_DOCUMENT_CATEGORY) и сортируются по полю SEQUENCE.

**Ожидаемый ответ:**
```json
{
    "result": [
        {
            "category": "Удостоверение личности",
            "sequence": 1,
            "documents": [
                {
                    "id": 1,
                    "documentCode": "PASPORTRF",
                    "name": "Мой паспорт",
                    "defaultName": "Паспорт РФ",
                    "sequence": 1
                }
            ]
        }
    ]
}
```

**Что проверяем:**
- Код ответа HTTP 200
- Наличие поля `result` в ответе
- Список документов (возможно пустой, если документы ранее не добавлялись)

### Шаг 2. Загрузить новый документ

#### Шаг 2.1. Запросить список доступных типов документов

**Метод:** `POST {{Server}}/document/getPersonalDocumentTypes`

**Тело запроса:**
```json
{}
```

**Описание:**
Метод MO001 — предназначен для получения списка типов документов и перечня их реквизитов для последующего создания персонального документа пользователя.

**Ожидаемый ответ:**
```json
{
    "result": [
        {
            "category": "Удостоверение личности",
            "sequence": 1,
            "documentTypes": [
                {
                    "documentCode": "PASPORTRF",
                    "defaultName": "Паспорт РФ",
                    "sequence": 1
                },
                {
                    "documentCode": "INTERNATIONALPASPORT",
                    "defaultName": "Загранпаспорт",
                    "sequence": 2
                }
            ]
        }
    ]
}
```

**Что проверяем:**
- Код ответа HTTP 200
- Наличие категорий и типов документов
- Сохраняем `documentCode` выбранного типа (не ОМС) — например, `PASPORTRF`

#### Шаг 2.2. Запросить параметры выбранного для загрузки типа документа

**Метод:** `POST {{Server}}/document/getPersonalDocumentParameter`

**Тело запроса:**
```json
{
    "documentCode": "PASPORTRF"
}
```

**Описание:**
Метод MO003 — предназначен для получения списка параметров документа при создании нового документа. Передается `documentCode` — код типа документа.

**Ожидаемый ответ:**
```json
{
    "result": [
        {
            "id": 1,
            "parameter": "Название",
            "required": true,
            "sequence": 1,
            "type": "STRING"
        },
        {
            "id": 2,
            "parameter": "Серия и номер паспорта",
            "required": false,
            "sequence": 2,
            "type": "STRING"
        },
        {
            "id": 12,
            "parameter": "Фотографии",
            "required": false,
            "sequence": 12,
            "type": "IMAGE"
        }
    ]
}
```

**Что проверяем:**
- Код ответа HTTP 200
- Список параметров с их типами (STRING, DATE, GENDER, IMAGE)
- Наличие обязательных параметров (required: true)
- Запоминаем id параметров для формирования запроса сохранения

#### Шаг 2.3. Загрузить изображение для нового документа (JPEG)

**Метод:** `POST {{Server}}/document/uploadPersonalDocumentImage`

**Content-Type:** `multipart/form-data`

**Тело запроса:**
- Параметр `file`: файл изображения в формате JPEG

**Описание:**
Метод MO006 — предназначен для загрузки в МС Хранилище файлов изображений документов. Сервер выполняет оптимизацию (сжатие) изображения перед загрузкой в хранилище.

Допустимые форматы: png, bmp, jpg, jpeg, gif, heic, heif, tiff, raw.

**Ожидаемый ответ:**
```json
{
    "result": "b4d5d63f-47f1-4c2a-8d7f-f5d3a57f65b0"
}
```

**Что проверяем:**
- Код ответа HTTP 200
- В `result` возвращается идентификатор (UUID) загруженного изображения
- Сохраняем ID изображения для использования в шаге 2.4

---

#### Шаг 2.4. Сохранить новый персональный документ с заполненными параметрами

**Метод:** `POST {{Server}}/document/savePersonalDocument`

**Тело запроса:**
```json
{
    "documentCode": "PASPORTRF",
    "parameters": [
        { "id": 1, "type": "STRING", "value": "Мой документ" },
        { "id": 2, "type": "STRING", "value": "88 00 654321" },
        { "id": 3, "type": "STRING", "value": "УФМС России" },
        { "id": 4, "type": "DATE", "value": "2020-05-15" },
        { "id": 5, "type": "STRING", "value": "770-001" },
        { "id": 6, "type": "STRING", "value": "Иванов Иван Иванович" },
        { "id": 7, "type": "GENDER", "value": "Мужской" },
        { "id": 8, "type": "DATE", "value": "1995-03-10" },
        { "id": 9, "type": "STRING", "value": "г. Москва" },
        { "id": 10, "type": "STRING", "value": "г. Москва, ул. Примерная, д. 1" },
        { "id": 11, "type": "STRING", "value": "Тестовый комментарий" },
        { "id": 12, "type": "IMAGE", "value": [{ "id": "<imageId из шага 2.3>" }] }
    ]
}
```

**Описание:**
Метод MO004 — предназначен для создания нового документа. Передается `documentCode` и массив `parameters` со всеми заполненными параметрами документа. Для параметра с типом IMAGE передается массив идентификаторов изображений из шага 2.3.

**Ожидаемый ответ:**
```json
{
    "result": "OK"
}
```

**Что проверяем:**
- Код ответа HTTP 200
- `result` = "OK"

### Шаг 4. Изменить параметр загруженного документа

**Изменяемые параметры:**
- **id=1 (Название):** `"Мой документ"` → `"Мой документ (обновлено)"`
- **id=11 (Комментарий):** `"Тестовый комментарий"` → `"Обновленный комментарий после редактирования"`

**Метод:** `POST {{Server}}/document/savePersonalDocument`

**Тело запроса:**
```json
{
    "id": "<documentId из шага 3>",
    "parameters": [
        { "id": 1, "type": "STRING", "value": "Мой документ (обновлено)" },
        { "id": 2, "type": "STRING", "value": "88 00 654321" },
        { "id": 3, "type": "STRING", "value": "УФМС России" },
        { "id": 4, "type": "DATE", "value": "2020-05-15" },
        { "id": 5, "type": "STRING", "value": "770-001" },
        { "id": 6, "type": "STRING", "value": "Иванов Иван Иванович" },
        { "id": 7, "type": "GENDER", "value": "Мужской" },
        { "id": 8, "type": "DATE", "value": "1995-03-10" },
        { "id": 9, "type": "STRING", "value": "г. Москва" },
        { "id": 10, "type": "STRING", "value": "г. Москва, ул. Примерная, д. 1" },
        { "id": 11, "type": "STRING", "value": "Обновленный комментарий после редактирования" },
        { "id": 12, "type": "IMAGE", "value": [{ "id": "<imageId>" }] }
    ]
}
```

**Описание:**
Повторный вызов метода MO004, но для редактирования существующего документа. Вместо `documentCode` передается `id` ранее созданного документа. Все параметры передаются заново, при этом параметры id=1 и id=11 содержат обновленные значения.

**Ожидаемый ответ:**
```json
{
    "result": "OK"
}
```

**Что проверяем:**
- Код ответа HTTP 200
- `result` = "OK"

## 4. Примечания

1. **Basic Auth** (`qa` / `1q2w3e4r5t6y`) необходимо указывать в **каждом** запросе к серверу.
2. **Cookies** `JSESSIONID` и `_bcspks` устанавливаются после авторизации (шаг 0) и автоматически используются Postman в последующих запросах.
3. **Логи** каждого запроса доступны по адресу `http://test.b-s-c.ru/logs/{{нода}}/api/bcs-api.log` (нода определяется при первом запросе).
4. **Тип документа ОМС** не используется по условию задания.
5. При **создании** документа передается `documentCode`, при **редактировании** — `id` существующего документа.
6. Параметры документа зависят от выбранного типа (`documentCode`). В примерах выше используется тип `PASPORTRF` (Паспорт РФ).
7. Перед загрузкой изображения (шаг 2.3) необходимо подготовить файл в формате JPEG.

  3. Выполнять запросы последовательно от шага 0 до шага 5

  5. Проверять логи на сервере по адресу `http://test.b-s-c.ru/logs/`
